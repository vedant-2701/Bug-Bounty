# Track 07 — Reporting & Professionalism

Purpose: applies from your first valid finding onward — don't treat this as a "later" track.

### Report Writing & PoC Craft 🔑
**Purpose:** a great finding with a bad report gets triaged slowly, downgraded, or missed entirely — this is a genuinely separate skill from finding the bug.
**Prerequisites:** at least one real or lab-based finding to practice on
**Core concept:** clear summary → reproducible steps → evidence (requests/responses/screenshots/video) → business + security impact stated separately → suggested fix.
**Primary resource:** HackerOne's own "how to write a good report" guidance
**Secondary resources:** read 10+ highly-upvoted disclosed reports on Hacktivity specifically for structure, not content
**Practice:** write a full report for a PortSwigger lab as if it were a real bounty submission
**Real-world example:** any top-voted Hacktivity report
**Cross-links:** bounty: Track 05 (chaining) — chained findings need extra-careful impact articulation
**Expected outcome:** can write a report a triager could act on without needing to ask a single clarifying question
